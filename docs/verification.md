## 2. 参考机记录

参考机的手动流程结果：

- 写入前 `devinfo` 为 `ANDROID-BOOT! 00 00 01`，`0x90=1`。
- 候选与原件逐字节比较，只有偏移 `0x0D`、`0x0E` 不同。
- 写入后回读 4096 字节，逐字节等于候选。
- `fastboot getvar unlocked` 返回 `unlocked: yes`。
- `fastboot getvar secure` 返回 `secure: yes`。
- `fastboot getvar product` 返回 `taro`。
- 手机端选择“清除所有数据”后，原系统正常启动。
- Android 属性变为 `ro.boot.flash.locked=0`、`vbmeta.device_state=unlocked`、`verifiedbootstate=orange`。

## 3. 第二台报告

仓库维护者收到第二台独立设备成功解锁的报告。该报告没有公开：

- 设备序列号
- 完整固件包或分区备份
- 原始 fastboot 输出
- 完整操作日志

因此：

- 它足以说明方案已经在至少两台独立设备上成功；
- 但它不能被当作第二份完整可复现证据；
- 仓库不会用第二台的镜像或备份去覆盖任何参考数据。

## 4. 已验证与未验证

已验证（以参考机为主）：

- `devinfo` 两个状态字节能让 ABL 返回 `unlocked: yes`。
- 写入后回读一致。
- 清数据后系统能正常启动。
- Android 属性与 fastboot 状态一致。

未验证：

- 能否刷入未签名/第三方 `boot`、`system`、GSI。
- 永久 Root 在所有固件上的兼容性。
- 所有 `PD2301[_字母]` 变体、所有批次、所有区域版本。
- OTA、官方修复、整包刷机后状态是否保留。
- 第二台设备的完整日志和分区布局。

## 5. 结论

两台独立成功报告说明方案在至少两个样本上成立；但解锁仍然是高风险的非官方操作。请以自己设备的工具检查、备份和回读结果为准。
